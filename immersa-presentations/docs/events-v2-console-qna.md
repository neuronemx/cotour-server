# Events v2 Phase 1C — Q&A console bridge

The fixed, cookie-authorized Stage, Speaker, Player and Público consoles now use the existing EventQnaRuntime/QnaRepository. No new engine, migration, public flag, production reader or legacy handler is introduced.

After an authorized Live join, the client reads Q&A state without initializing it. Stage/Speaker open Q&A, toggle intake, select/project questions, hide the projection, delete never-projected questions and create a new round. Delete/new-round require confirmation bound to the current round. Closing the projection preserves intake/history. Q&A stays available beside an active poll.

Público gets only its current round/intake, saved name and own receipt/cooldown. The name defaults to the event registration and supports a correction; consent to screen display is explicit per question and off by default. Draft/name edits survive ordinary updates. A confirmed receipt clears the question/consent; round changes, loss of authority and finish clear private UI. Cooldown expiry requests a fresh authorized snapshot; it never locally claims acceptance or replays submit. The existing ten-second server cooldown permits later questions; it is not one question per round.

Player output shows only the canonical projected text and consented name. The existing generic candidate IDs/labels support select/project/delete without exposing unprojected inbox text or names. The complete Q&A cycle and poll cycle share one emergency menu: E, vertical arrows, Enter, Escape. Only one action/title line appears. Delete/new-round require a second deliberate Enter on a confirmation action. A changed round/run/action invalidates the displayed selection. Editing, repeats and modifiers are excluded; horizontal emergency slide arrows remain separate. E still needs physical browser/operator acceptance.

The transport admits exact Q&A field allowlists only. Event/Live/actor/role are not caller inputs. Controller generation, Live binding and revision fences reject stale replies. Every command and recipient remains authorized by the server. An uncertain acknowledgement reconnects through a fresh cookie check and reads canonical state without replay. New rounds and projected-question deletion restrictions remain backend decisions.

Focused tests execute the shipped controllers, transport and page handlers with a DOM model, including literal text, drafts, consent, timers, confirmation, authority loss and a combined menu. The added real SQL/HTTP/Socket.IO suite uses controlled private preparation and shipped modules for all four roles, own name/receipt across tabs and reconnect, real dropped submit ack, complete Player cycle, consent, poll coexistence, new/stale rounds, revoke and isolated finish. Its clients close in finally. A Node cookie jar/DOM model is not browser render/Secure-cookie acceptance.

Phase 1C/1 remain open. Private preparation/readers and real slide rendering, other interaction UIs, rehearsal, Venue/Signals and portal remain pending. Public v2 stays off; no DNS for show.immersalive.com yet. Durable commands/restart/multi-instance execution remain Phase 3. CI and the isolated Temporal pilot must be recorded against the final SHA before treating this increment as validated.
