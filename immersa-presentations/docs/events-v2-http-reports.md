# Events v2 — Phase 1C authorized HTTP history and exports

Account-authenticated Admins of the specific event may read and export durable Q&A and Trivia/Evaluation results and aggregate reactions. Capabilities event.metrics.read/export are explicit additions to ADMIN; Producer, organization membership alone, platform administrator and operational Speaker/Stage/Player/Público grants confer no report access. No Presentaciones plan is substituted for Events authorization. Producer delegation of report permissions remains unavailable; no implicit nominal access.

Routes under /api/events-v2/organizations/:orgId/events/:eventId/live-sessions/:liveId:

- GET qna/history and qna/export.csv: committed retained questions across rounds.
- GET knowledge/history: execution metadata without names or answers.
- GET knowledge/:executionId/results and knowledge/:executionId/export.csv: persisted final results only, assessment rows or Trivia Top 10. Before persisted calculation: 409 REPORT_RESULTS_NOT_READY.
- GET reactions and reactions/export.csv: aggregate heart/clap/fire and total, exact decimal strings.

Every request locks the organization, revalidates current event membership/capability and resolves the canonical LiveSession with its event/activity/stage chain. Separate storage bindings check stage/activity/deck/version/source; execution snapshots and results check execution/live/source/deck/category. Q&A participant ownership and each page of result participants are validated against the event before nominal delivery. Sharing a Deck, organization, legitimate membership in two events or a cursor never authorizes cross-scope resources. No operational token in path/query/Authorization becomes an account. Account and operational credentials do not combine scopes.

Historical reports allow finished sessions after current account authorization; they need no active engine, private preparation reader or live grant and never create sessions, counters, participants or engine state. They read SQL history, not public catalogs or live snapshots. Deleted Q&A questions remain deleted. Successful reads/exports record minimal security audit actor/action/event/resource; no names, answers, credentials or CSV body in audit. Responses are built inside the authorized transaction and sent only after commit and a fresh feature check. Failed commit/DB outage returns sanitized 503, with no nominal content. Revocation uses the same organization lock; operations authorized before its commit may complete, subsequent requests deny. Previously downloaded data cannot be revoked.

Pages default to 100, maximum 500. Q&A and knowledge history use an after UUID resolved within the same LiveSession and stable timestamp/ID ordering; JSON returns nextAfter, CSV X-Report-Next-After. Results use offset on immutable calculated rows and nextOffset / X-Report-Next-Offset. CSV X-Report-Row-Count identifies each page; a response is one page, never an implicit full-event export. Complete downloads require fetching pages. Unknown/duplicate/invalid query fields deny; cursor/offset supplies position, no authority. Result page JSON is extracted in SQL by bound fixed-index paths, without hydrating participant recovery secrets or all answers. No recovery hashes/tab IDs/attempt IDs/participant IDs/correctOptionId or arbitrary stored payloads are returned; explicit allowlisted definitions/results only.

The existing knowledge CSV formatter is reused with an injected cell serializer, preserving Presentaciones defaults. Fields are quoted and quotes escaped; text with formula/control prefixes and long decimal strings receives an in-field tab. JSON retains exact original text. This is a human-viewing CSV mitigation, not a universal guarantee across applications/resaving/import pipelines; no Excel/LibreOffice manual certification. References: [OWASP CSV Injection](https://github.com/OWASP/www-community/blob/master/pages/attacks/CSV_Injection.md), [MySQL JSON_EXTRACT](https://dev.mysql.com/doc/refman/8.4/en/json-search-functions.html), [MariaDB JSON_EXTRACT](https://mariadb.com/docs/server/reference/sql-functions/special-functions/json-functions/json_extract).

Headers: no-store/no-referrer/nosniff/same-origin resource policy; fixed UUID-based attachment filenames, no user-provided filename/path. HEAD still authenticates/authorizes; conditional requests never bypass authorization. Cross-site Fetch Metadata denies. No new clear/delete operation. Legacy Deck history/metrics and link exports still deny v2 resources even with the feature off; a new explicit execution-ID boundary denies Events knowledge executions under the legacy export route even with a valid personal Deck link. Presentaciones/v1 retain their routes and defaults.

Contract 2.1 requires 50 simultaneous Screen reactions. This increment corrects Events from the inherited 40 to configurable 50; default Presentaciones remains 40. All accepted reactions still count, own-window privacy and spam limiter unchanged. Backend transport/model cap only; Events rendering remains pending.

No schema migration. No historical poll or raffle reports are fabricated from transient/current state; their durable history, event-wide Dashboard, attendance/concurrency/billing statistics, lifecycle/consoles/other families remain pending. Feature off, private production readers absent, no portal/DNS work. Phase 1C stays open, Temporal only, no merge/deploy to Main/Beta/Production. Full Command Service/idempotence/restart recovery/multiinstance capacity remain later phases.
