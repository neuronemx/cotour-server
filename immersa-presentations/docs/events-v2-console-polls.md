# Events v2 — authorized poll consoles

The shipped access client, Live controller and poll controller connect the generic four-function console to the existing EventPollRuntime/InteractionStore. This is a UI/transport bridge, with no new voting or aggregation engine, schema, production reader, public flag or legacy change.

After an authorized Live join, a poll snapshot obtains the fixed private catalog. Stage/Speaker see titles, questions and aggregates and may launch, show/hide and close. Player receives only the current question, permitted visible aggregates and catalog IDs/titles for emergency operation. The one-line emergency selector uses E to open, Up/Down to choose, Enter to execute and Esc to dismiss; repeat, modifiers, editable/form focus are excluded. The catalog/control panel and internal active title are absent from its output. The prior emergency slide arrows remain available.

Public sees the active single-choice question/options and only its own receipt. It receives no catalog, aggregates, other identities or control fields. Selection is retained across updates and radios are not rebuilt during an ordinary receipt/state update. The UI claims a vote only from the authorized receipt; cookie reconnect restores it. Duplicate/stale-run denial refreshes by read, never submits again. A genuinely lost command ack clears state, reauthorizes and reads the committed result without replaying mutations or creating identity/attendance/runs.

Payload allowlists prohibit event, LiveSession, role, actor and arbitrary definition claims. The poll controller binds to the authorized Live controller's current event/execution, fences late acks by generation, ignores older/foreign projections and clears on loss/revoke/finish. It bounds and strips server projections before rendering literal text and count/percentage bars. The server still enforces private preparation/version/catalog, one vote per participant per run, serial execution, inter-family conflicts, current grant and every recipient's scope. Normalized translations are retained; a multilingual UI selector is not delivered in this increment.

Focused tests execute the real modules and page handlers against a DOM model. Four additional real SQL/HTTP/Socket.IO blocks cover prepared catalogs/private projection, own receipt/two-tab/reconnect, genuinely lost vote ack without replay/duplicate writes, and Player cycle/relaunch/stale run/revoke/finish isolation. Their reader is a controlled fixture; DOM and a Node cookie jar do not establish physical browser rendering or Secure-cookie acceptance. The integration fixture closes clients in finally even on assertion failure.

Remaining Phase 1C/1 work includes other interaction/media/time UIs, private slide renderers, rehearsal, Venue/Signals/portal and browser/operator acceptance. Production preparation/readers remain Phase 2 and durable multi-instance command execution Phase 3. Public stays off; show.immersalive.com does not require DNS. No Main/Beta/Production changes or merge. Rollback to #284 retains the authorized access/navigation/lifecycle baseline without reverting data.
