# Events v2 — Phase 1C Juegos and Time

Games uses the real BreakoutStore, PongStore and GameQueueStore with constructor-scoped STAGE/SPEAKER/PLAYER controls. Their default Presentaciones roles and physics are unchanged; no legacy socket handler or fabricated presenter/stage context is used. The trusted private preparation reader selects the available Breakout/Pong definitions and bounded server durations. Production reader remains absent and Events stays off; no demo/catalog/media fallback.

Configure selects prepared game IDs; queue start requires the current revision and prepares the first game in fixed difficulty order. Each game has a server UUID. Breakout runs its lobby, collective input and four-second countdown, pause/resume and server-time finish. Pong supports names, identity-deduplicated teams, readiness for both currently connected/authorized teams, locked roster/spectators, pause/resume, real collective physics and terminal winner/tie. A finished game advances to the next prepared lobby after five seconds under a freshly authorized controller; final results remain until end. Skip/end validate current queue ID/revision. Game commands/input validate the current game ID, rejecting stale/cross-run packets.

Participants come from grants, never supplied audience IDs. Short-session/grant/issuer/resource/live access is revalidated on commands and each recipient delivery. Pending Breakout/Pong inputs are filtered against connected fixed-live peers via sessionOn on the caller's existing organization transaction, without nested pool/transaction. Pong's initial ready teams are similarly checked. Multi-window/reconnection shares participant rate limits/team membership. Only controller credential witnesses drive automatic frames/transitions; at most twelve are retained and each is reauthorized. No raw room broadcast or public legacy event is accepted.

Games and all other primary interactions (polls, raffle, trivia/assessment) exclude each other by LiveSession under the shared queue and organization lock. Q&A and Time coexist. All game stores/candidates are cloned before mutations and installed only after committed authorization. Rejected/rolled-back preparation, input, physics and Time commands cannot publish candidates. State is process-local, not restart-durable or distributed. Full Live recovery, idempotence/uncertain COMMIT and efficient high-volume authorization belong to Phase 3. The 50 ms loop is a target cadence; SQL and per-recipient authorization latency determine actual cadence. Capacity, latency and high-concurrency play are not certified by functional tests.

Stage/Speaker get operational game/queue snapshots without roster/input actor IDs. PLAYER gets Screen physics and full emergency controls, omitting roster counts. Público gets status/control data and only its own Pong membership, no physics, other identities or queue catalog. Time reuses immersa-time-runtime: independent Speaker stopwatch and Screen stopwatch/countdown/clock, strict target/action/mode/time-parts and expected revision. Server clock alone determines elapsed/remaining time. Expired countdown stays visible at zero until reset/hide; a valid command freezes expiration before transition. PLAYER sees only Screen Time, Público gets no Speaker or Screen Time data. Reading idle Time/Games never installs state. Time controls do not start/finish a LiveSession: authorized session lifecycle is a separate pending increment.

Protocol: events:game:snapshot/configure/start_queue/skip/end/start/pause/resume/team_names/join_team/input; configure {expectedRevision,selected}, start_queue {expectedRevision}, skip/end {expectedRevision,queueRunId}, game controls {gameRunId}, names {gameRunId,left,right}, team/input {gameRunId,team|direction}. events:time:snapshot/control uses {expectedRevision,target,action} plus mode for Screen start and hours/minutes/seconds only for countdown. No client identity/configuration/clock authority. Frontend consoles, keyboard/audio/intro/private asset delivery and remaining families/HTTP/media/export stay pending. Temporal only; no Main/Beta/Production deployment or merge. show.immersalive.com DNS is not required yet.
