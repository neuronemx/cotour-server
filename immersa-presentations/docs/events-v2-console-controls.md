# Events v2 — first operational console controls

This increment connects the existing private console entry to canonical Events navigation and Stage lifecycle. It uses the same SQL authority and execution engines; it introduces no new lifecycle engine, migration or public entry.

The authenticated console metadata endpoint returns a bounded catalog of active-stage, scheduled/live activities inside the fixed grant's event and resource. Stage sees its own stage; Speaker sees its fixed live-purpose activity; Player sees its fixed execution. Audience sees only live activities permitted by its current FREE/PAID level. Rehearsal has no operational targets. Titles are rendered as literal text only after authorization. Deck IDs, preparation versions and private resources are not part of the catalog. `canStart` describes an eligible Stage attempt; the server still requires valid private preparation and rolls back an unavailable reader.

Stage and live Speaker have previous/next, slide selection and pause/play controls. Only Stage can start a selected scheduled activity and finish a bound live presentation. Finish requires a confirmation dialog. Player has emergency left/right arrows with repeat/modifier/form-focus exclusions. Audience can choose permitted live activities and receives the visible position; it receives no presenter index, total count, pause owner or control payload. This UI displays positions, not private slide files. It explicitly states that private file visualization is unavailable.

The shared access transport admits only exact Events navigation, read/join and lifecycle payloads. Pending acknowledgements are fenced by connection generation and canceled on loss. A lost acknowledgement never causes a mutation replay: recovery reauthorizes the cookie, reloads the catalog and joins/reads the committed state on a fresh socket. A different execution requires a fresh connection, including when a prior join failed. Stale event/run/revision responses cannot replace current state. Denial, loss and terminal finish clear usable projections and controls.

Focused tests execute the actual access client, controller and page handlers against a small DOM model. Four additional integration blocks execute the shipped modules against real SQL, HTTP and Socket.IO: catalogs and FREE/PAID scope, Stage-only start, shared navigation/pause and restricted projections, real lost-ack recovery without duplicate actors/grants/attendance/runs, finish isolation, missing preparation rollback and revocation. Their private preparation reader is a controlled test fixture, never a production reader. The DOM model and Node cookie jar do not establish physical browser rendering, Secure-cookie behavior or operator acceptance.

Phase 1C/Phase 1 remain open. Other mature interaction/media/time control UIs and private renderers, functional rehearsal, Venue/Moderation/Signal/portal and physical browser/operator acceptance remain pending. Production preparation/readers and ownership belong to Phase 2; durable command execution belongs to Phase 3. The public flag remains off; no DNS action for show.immersalive.com is required. Main/Beta/Production are unchanged. Rollback to the preceding console-access head removes these controls while retaining the perimeter and access transport, without reverting data.
