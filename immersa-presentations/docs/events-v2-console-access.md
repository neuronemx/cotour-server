# Events v2 — first console access increment

Technical entry: `/events-v2/console/{stage|speaker|screen|audience}/{eventId}/{grantId}#token={secret}`. The long token belongs only in the fragment. A reload uses the same path without the fragment and restores the existing HttpOnly cookie; audience entry starts from its already registered cookie. This is an internal pilot path, not the future public slug portal.

The generic HTML lives outside `public/`, is flag-gated and sends no-store/no-referrer/CSP headers. Static JS/CSS contain no event data. No legacy console script, socket namespace or default deck is used. The same client handles all four grant kinds without deriving privileges from a selected UI function.

The fragment is removed synchronously before requests, including invalid fragments. Exchange uses a same-origin POST; the long credential is held only in memory while an initial exchange needs retry, and discarded on success, terminal denial or close. It is never put in cookies by JS, storage, request URLs, history state, socket auth, rendered state or telemetry. The server alone sets its Secure/HttpOnly/Strict/host-only cookie. Short socket credentials stay in memory and are cleared from retired sockets.

`GET /api/events-v2/access/{eventId}/{grantId}/console/{view}` validates the fixed browser credential, current issuer/resources and matching grant kind before reading the event title under the same transaction. The response contains metadata only. Query claims, cross-site reads, wrong function and cross-event credentials are denied. The page renders the name with textContent after authenticated socket context, never by interpolating HTML.

Socket.IO always connects to `/events-v2`, forceNew, without automatic cached-auth reconnect. Only the server context makes access ready. Idle short-session renewal uses the existing `events:session:renew` operation on the same connection. A transport loss or missed ack clears usable context and reauthorizes through the browser cookie before creating a new socket. A 401/403/404 or malformed/mismatched response ends access; transient availability failures retry with bounded backoff. Timers, in-flight HTTP and late responses are fenced on close. Returning to a visible/online page checks the cookie again; a restored page after pagehide reloads rather than reviving a closed client.

The fixed event/grant/function/actor/resource binding cannot be changed by later metadata or socket packets. Renewal never extends the event's operational window, creates a grant/participant/attendance or starts a LiveSession. The backend continues validating every operation and recipient; client checks supplement that authority.

Focused tests cover secret removal, ambiguity, no-ready-before-context, credential separation, cookie reconnect, on-socket renewal, late HTTP/acks, wrong scope, terminal denial and initial outage/close. The real SQL suite runs the browser client module against HTTP/Socket.IO: all four kinds, scheduled lease renewal, expired-session cookie reconnect, audience cookie reload, wrong function/event, revoke, DB failure and the flag. Its controlled timer drives the actual long-lease callback without a 15-minute test wait; SQL, HTTP, socket auth and renewal are real.

Limits: this delivers a shared access client and generic access shell. It does not convert the mature presentation controls/renderers, join prepared Live content, implement functional rehearsal, read private preparation, register a new audience automatically or deliver Venue/Moderation/Signal/portal. The shell says content operation is unavailable. Those UI connections and their browser/operator acceptance remain pending; Phase 1C/Phase 1 are not declared closed by this increment. Production readers/ownership remain Phase 2 and durable command execution Phase 3. Public flag remains off; show.immersalive.com does not require DNS yet.
