# Events v2 — Phase 1C Trivias and Evaluations

This adapter reuses the existing pure Knowledge engine and repository persistence semantics. Real typed STAGE/SPEAKER/PLAYER grants authorize pure transitions directly, without creating legacy presenter/Stage sessions or invoking legacy socket handlers. PARTICIPANT joins and answers use the grant's participant identity and a server-generated socket tab ID. Client roles, participant IDs, deck IDs, timestamps and tab IDs are never accepted as authority.

Migration 040 adds seven separate Events tables: canonical live-bound preparation context plus executions, participants, orders, answers, results and reserved command storage. Context stores stage/activity/deck/version/catalog digest and latest execution pointer; the adapter verifies those relations against the currently authorized live and private catalog. Only explicit activation creates context/execution. Active-session uniqueness prevents concurrent executions. Re-runnable DDL recovers after a partial migration. Repository Events mode requires the caller's connection/transaction, uses fixed SQL table identifiers and portable JSON parameters, and blocks legacy session creation/global restoration/history. Default Presentaciones behavior stays unchanged.

The private reader must match event/live/deck/version; normalized definition digest cannot change under the same preparation. Text definitions use the existing normalization allowlist. Historical /decks images are rejected until the private asset boundary is implemented. The deployed reader remains absent (no demo/public fallback); fixtures supply scoped catalogs only in isolated tests. Public Events remains disabled.

Socket names: events:knowledge:snapshot/open/start/finalize/cancel/show_results/close/retry_processing/force_results/join/claim_tab/answer/submit. Open accepts only definitionId; controller actions accept executionId and expectedRevision. Admission accepts executionId and optional name; claim/submit accepts executionId. Answer accepts executionId/questionId/optionId/attemptId. The socket adapter injects its own tab ID. Run IDs reject packets from earlier/other executions. A valid grant is rechecked before all transitions and each recipient send, including deadline ticks. SQL commits before acknowledgment/fanout; failed authorization, reads or pre-COMMIT rollback cannot publish a candidate.

Stage/Speaker can inspect the existing controller DTO. PLAYER can run the full emergency state cycle but receives the existing Screen DTO: no future definitions, unprojected options/correct keys, individual assessment rows or private results. Público sees only its own answers/receipt and shuffled question/options. Contest correct answers appear only during reveal/results; assessment grades only after show_results. Event names prefill named admission, nonblank correction persists, blank preserves the identity, and failed admission rolls the correction back. Anonymous participation uses a generic label in its execution. Reconnect recovers orders/answers/results from SQL, then explicit admission/claim moves the active tab; another window cannot forge the socket tab ID.

Polls, contests and assessments exclude each other in one live execution using the shared queue and organization transaction lock. Q&A coexists. The poll engine is still process-local, so this does not claim durable cross-family exclusion across restart/instances. Deadline timers use an active scoped credential, reauthorize in SQL and send only after commit. If authorization expires or the process stops, a fresh authorized join/snapshot resumes reconciliation. SQL reconstruction of Knowledge state is verified; the full Live engine, general command retry/idempotence, uncertain COMMIT and distributed scheduling remain Phase 3 work. Persisted answer attempts prevent reuse across questions and safely recognize an already stored identical answer, without claiming general command idempotence.

This is an adapter increment, not the completion of Phase 1C. Operational UI/keyboard, private preparation/publication, other families and HTTP/media/export adapters remain pending. No Venue/Signal/Muro scaffolding, merges or Main/Beta/Production deployment. show.immersalive.com DNS is not needed yet.
