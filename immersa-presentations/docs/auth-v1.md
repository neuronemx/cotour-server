# IMMERSA Auth v1

Auth v1 is the account boundary for the IMMERSA Home and deck administration. Better Auth owns identity/session tables; IMMERSA owns personal workspaces and deck ownership.

## Product contract

- Google sign-in and email/password are the two entry paths.
- Email/password requires email verification before sign-in. The confirmation view can resend the verification email or return to registration to correct a mistyped address. Credential accounts that remain unverified for 48 hours, have never opened a session, and own no Decks are removed automatically.
- Password recovery is available from the Auth screen.
- Sessions are persistent unless the user explicitly signs out.
- Every new Better Auth user receives one invisible personal workspace with plan `FREE`.
- No plan or workspace choice appears during onboarding.
- `Mis presentaciones` contains only decks registered to the signed-in user's workspace.
- Home, upload, deck administration, deletion, and creation of presentation access links require the owning account.
- Speaker/Stage controller links remain usable without an account login and authorize their bounded live controller actions with their access token.
- Público, Screen, Viewer, and public presentation links do not require an account login.
- Runtime reads needed by those public roles stay outside account authentication.

The official product Deck Demo is a global system resource presented in every authenticated workspace through an isolated workspace Demo session. It is not counted as a user Deck or storage, grants Speaker Pro capabilities only in Demo mode, and cannot be renamed, replaced, deleted, duplicated, transferred, or edited as a normal Deck. Legacy development decks named `demo`, `demo01`, etc. are not the official product Demo.

## Production environment

Required to publish Auth v1 on `https://app.immersalive.com`:

```text
IMMERSA_AUTH_ENABLED=true
BETTER_AUTH_URL=https://app.immersalive.com
BETTER_AUTH_SECRET=<random secret, at least 32 characters>
GOOGLE_CLIENT_ID=<Google OAuth client id>
GOOGLE_CLIENT_SECRET=<Google OAuth client secret>
RESEND_API_KEY=<Resend API key>
IMMERSA_EMAIL_FROM=IMMERSA <access@auth.immersalive.com>
```

The existing MySQL/MariaDB variables remain required. `IMMERSA_ROUTE_GUARD_SECRET` should also be a stable production secret so live role cookies remain valid across process restarts.

### Google

Authorize this production callback URI in the Google OAuth client:

```text
https://app.immersalive.com/api/auth/callback/google
```

### Resend

Recommended transactional sending domain: `auth.immersalive.com`.

Verify that sending domain in Resend and publish the DNS records generated by Resend before enabling external email/password testing. The API key remains server-side; the browser never receives it.

Auth v1 sends only two transactional message types:

1. Email verification.
2. Password reset.

## Database

`npm run migrate` now runs:

1. IMMERSA SQL migrations, including `006_auth_workspaces.sql`.
2. Better Auth's schema migration when `IMMERSA_AUTH_ENABLED=true`.

IMMERSA tables added by Auth v1:

- `workspaces`
- `workspace_members`
- `decks`

Existing development deck files are intentionally not migrated into `decks`. As a result, they do not appear in a new user's `Mis presentaciones`.

## Smoke test before production

Use two distinct accounts, A and B:

1. Create A with Google and B with email/password.
2. Verify B's email.
3. Upload one deck from each account.
4. Confirm A cannot list, edit, create links for, or delete B's deck and vice versa.
5. Confirm session persistence after browser refresh.
6. Confirm sign-out returns to Auth.
7. Complete a password reset for B.
8. Open Público and Screen links in a signed-out/incognito browser and verify presentation runtime/interactions.
9. Open Speaker/Stage access links signed out and verify authorized live controls still work.
