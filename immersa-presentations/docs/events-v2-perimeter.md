# Events v2: legacy perimeter review (Phase 1C)

This review found and reproduced gaps in controlled fixtures: Express's case-insensitive routes did not match the boundary's case-sensitive expressions; IDs trimmed by legacy handlers were looked up before trimming; serve-static's decoded/dot-normalized aliases could reach a classified v2 Deck. Private fixture interactions and manifests returned 200 through those alternatives before the correction. This is fixture evidence, not a claim of exposure of real users' production data. Public Events remains off; production Events content preparation/readers are still absent.

The boundary now inspects both the original locator and the once-decoded, POSIX-normalized path, matches route prefixes without regard to case, and trims SQL lookup IDs as legacy repositories do. It does not rewrite req.url or change legacy Express routing. Malformed escapes/NUL return sanitized 400. Canonical classification still applies when the public feature or individual event is disabled. A configured SQL outage returns sanitized 503 before handlers/static byte delivery.

Covered locator families: event, Stage, activity, LiveSession, public QR, Speaker assignment, nested event Speaker/poll, Deck, and v2 Knowledge execution. Nested/body resource IDs are checked independently of the parent v1 event/Stage; a visible parent does not authorize a v2 child. Typed body fields are inspected only on the known legacy Event Hub/Stage families. Client roles do not participate in classification. Existing private assets/reports and grants remain on their separate authorized v2 routers.

Legacy socket join checks the normalized/defaulted session/deck identifiers before any state creation. Path-like Deck IDs and the reserved evt:event:live/venue:run execution namespace are denied. The actual Events namespace keeps fixed persistent grants, server-derived participants, per-command reauthorization and per-recipient projections; legacy packet names cannot select that namespace's private engines.

The unchanged inventory implementation is extracted to deck-inventory.js with an allowDeck callback. Server listings inject the Events classification check before manifest stat/read, ensureManifestSessionId or migration. Personal Deck ordering, summaries, deduplication and defaults remain. An explicit legacy-only caller's default remains permissive; this is not a v2 content reader. The server uses the boundary whenever its SQL-backed Events services are configured.

Access-link resolution checks stored session/deck scope before looking up a manifest; direct Deck-link creation also checks the known Deck ID first. Historical links without deck_id retain their existing lookup and final check. Phase 2's private ownership/storage/source-session catalog must ensure that new Events content is never placed in scanned personal/public roots. This increment does not migrate personal Decks into Events, certify symlink/storage ownership, or enable an offline Events fallback.

Tests exercise real legacy interaction readers and both real static roots, deny-before-migration inventory behavior, fixed link scopes, SQL classification, actual legacy start/finish, and Socket.IO denial before rooms/state. Fixtures use separate storage roots and disposable SQL only. No load/recovery or UI/Fallback certification.

The backend review strengthens the families already delivered. Phase 1C/Phase 1 remain open for the console access/exchange/renewal connection described in the current audit. Production ownership/preparation/rehearsal/readers remain Phase 2; durable Command Service, general idempotency/recovery/distribution remain Phase 3; Venue/Muro/signals and portal retain their phases. No merge or Main/Beta/Production deployment; show.immersalive.com does not need DNS yet.
