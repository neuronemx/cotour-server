# Events v2 — Phase 1C Audiovisual, overlays and private bytes

Audiovisual pure transitions are extracted from server.js into audiovisual-state.js and called by Presentaciones and Events. Default Presentaciones behavior, inline resource-selection authorization and role boundaries remain intact. Events uses real typed STAGE/SPEAKER/PLAYER grants, no legacy socket handler or fabricated role. Audio/video stay independent; current playback UUIDs guard stop/play/pause/seek/loop and Player ended/playlist feedback. Prepared resource/playlist IDs alone select media. Volume is shared and updates pending fades. One-second replace/stop fades preserve pending choice and use bounded reauthorized controller witnesses, never a captured legacy room. Candidates are cloned and installed only after the authorization transaction commits. Stale ended callbacks cannot stop replacements.

Trusted private preparation must match event/live/deck/version; bounded normalized definitions contain asset ID, hash, byte size, MIME and duration. Duplicate/unknown bindings, raw paths/media URLs and local-library publication are rejected. There is no public/demo/catalog fallback. Production preparation/asset readers remain absent, Events off. Delivery projects only same-origin, credential-bound asset endpoints, no raw storage path or reusable signed URL. Público has no AV catalog, channel, Audio React or asset access; allocated Player has the prepared catalog for that LiveSession.

GET/HEAD /api/events-v2/live/:eventId/:liveId/:grantId/assets/:assetId uses the existing fixed HttpOnly grant cookie. Each request revalidates grant/issuer/resource/event/live/current access and immutable preparation before obtaining a trusted verified descriptor. HEAD, conditional responses and invalid ranges never open bytes; range/full GET streams only after authorization commits, without holding SQL locks during playback. Single prefix/open/suffix byte ranges, 206/416 Content-Range, strong If-Range and authenticated 304 are handled. Responses use no-store, no-referrer, nosniff and same-origin resource policy. Unknown routes end here, without legacy fallback. Reader must supply immutable verified bytes and an opaque Readable opener; Phase 2 owns preparation, hashing and storage. Authorization is per HTTP request: it cannot revoke already delivered/buffered bytes or cancel an already authorized stream instantly. CDN/large-file capacity, physical media decode and private production reader delivery are not certified by the protocol fixture tests.

Overlays adapt live text, prepared event QR identity, slide-bound transient drawing and twelve Audio React modes. Text is plain data and must be rendered as text by future consoles; arbitrary HTML/URLs never become authorization. QR identity must currently belong to this event and be active; portal/hostname/QR URL generation stays pending, no legacy URL is fabricated. Drawing validates current live slide, finite normalized points, bounded width/TTL, 100 ms per-grant rate and 128 transient retained strokes. TTL and current slide filtering prevent old strokes on reconnect; clear_message/clear_screen remove transient state. Q&A, Time, primary interactions and AV/overlays coexist.

Reactions reuse ReactionRuntime's actual emoji allowlist, four-token burst/two per second limiter, own echo and 40 visible Screen cap/3100 ms lifetime. The class runs with buffered callbacks; no echo/screen candidate is emitted before commit. Migration 042 stores separate LiveSession-bound aggregate heart/clap/fire counters atomically on the caller transaction, including accepted reactions beyond visual cap. Idle/rejected reads never initialize counts. No nominal rows or legacy presentation metrics/history/import/export. Público receives only its sending socket's reauthorized echo, never other windows/people's reactions, totals or roster; Player gets at most 40 current opaque-ID visual reactions; Stage/Speaker get aggregate counts. SQL totals survive reconstruction, while limiter/visual/media/overlay state remains process-local. Full recovery/idempotence/uncertain COMMIT and multiinstance control remain Phase 3.

Protocol events:av:snapshot/control/audio_react/overlay/draw/clear_message/clear_screen/react/ended/playlist_advance. Strict per-command field allowlists reject raw client identity, source URLs, assets/config, clocks and stale playback IDs. Every recipient revalidates current access before projection; no room broadcast. Feature-off, revoke, FREE→PAID and finished live deny new commands/asset requests and deliveries. Renderers, keyboard/audio/video decode, private prepared slides and remaining HTTP/export/lifecycle/consoles/Brand Mentions/Venue families remain pending; this increment does not close Phase 1C or publish Events. Temporal only, no Main/Beta/Production merge/deploy. show.immersalive.com DNS is not needed yet.
